# 개인 Next.js·React 프런트엔드 패턴

새 프로젝트에서도 익숙한 방식으로 작업할 수 있도록, 반복되는 구현 기법과
구체적인 예제를 모은 개인 작성·dotfiles 관리 Skill입니다.
기존 제품의 기능이나 업무 규칙을 새 프로젝트의 기본값으로 복사하지 않습니다.
에이전트가 따르는 계약은 같은 디렉터리의 `SKILL.md`가 기준입니다.

## 구성 원칙

- **실행 가능한 기본 구성:** 도구, Provider, 공통 UI primitive와 검증된 유틸리티.
- **필요할 때 적용하는 패턴:** 인증·locale 라우팅, 폼, 목록, 상세 조회, 변경 요청, 날짜, 파일 업로드.
- **프로젝트에서 결정할 사항:** 권한, API, 검색 의미, 페이지네이션 방식, 시간대,
  입력 제한, 낙관적 처리, 승인 절차 등.

여러 제품에 같은 코드가 있다는 사실만으로 공통 정책이라고 판단하지 않습니다.
반복 사용 근거가 분명한 유틸리티는 포함할 수 있지만, 제품 규칙과 결합되어 있다면
그 구현 기법만 참고 예제로 남깁니다. 관련 판단은 `references/adoption.md`에 있습니다.

## 요청 방법

사용하는 에이전트에 이 Skill을 연결한 뒤, 이름과 구체적인 요청을 함께 전달합니다.
Skill 검색과 호출 방식은 클라이언트마다 다르며 OMP를 전제로 하지 않습니다.

```text
frontend-patterns를 사용해서
이 프로젝트의 API 계약에 맞는 목록 화면을 만들어 주세요.
검색 조건과 페이지네이션 방식은 기존 명세를 먼저 확인해 주세요.
```

다음과 같은 요청에도 해당 주제의 참고 문서를 선택해서 적용할 수 있습니다.

- “기존 백엔드 계약에 맞춰 locale 검증, `proxy.ts`, 로그인·로그아웃 Server Action과 쿠키 갱신 흐름을 설계해 줘.”
- “기존 디자인에 맞춰 RHF/Zod 폼을 구현하고 Enter 제출과 오류 표시를 확인해 줘.”
- “읽기 전용 상세 Sheet를 추가하되, 캐시 데이터가 있으면 새 요청 중에도 보여 줘.”
- “이 편집 화면은 최신 정보와 revision이 필요해. 저장 실패 시 초안을 보존해 줘.”
- “업로드 API는 이미 있어. 파일 선택과 검증, 실패 후 재시도 UI를 연결해 줘.”
- “이 유틸리티가 재사용 가능한 공통 코드인지, 제품 코드인지 검토해 줘.”

구체적인 기능 요청이 없으면 예제가 있다는 이유만으로 페이지, API, 폼을 만들지 않습니다.
사용자가 호출해야 하는 인터뷰나 별도 워크플로도 자동으로 시작하지 않습니다.

[locale 라우팅과 Proxy](references/auth-routing.md)는 경로 판별, 안전한 복귀 URL,
`proxy.ts`를 완전한 코드 예제로 보여줍니다.
[세션과 인증](references/auth-session.md)은 쿠키 갱신, 로그인·로그아웃 Server Action,
서버 인가와 세션 전환을 다룹니다. 실제 백엔드에 연결해야 하는 계약은 명시하며,
인증 방식·역할·API·토큰 수명을 임의로 정하지 않습니다.
예제는 문서에만 있으며 대상 프로젝트에 실행 가능한 인증 코드나 `proxy.ts`를 자동으로 추가하지 않습니다.

## 예제를 사용하는 방식

참고 문서는 적용 조건, 필요한 제품 결정, 완전한 코드 예제와 확인 시나리오를 제공합니다.
코드는 명시된 파일 단위로 읽고, 연결된 예제 모듈과 실제 백엔드 계약을 함께 확인합니다.

예제의 서비스 함수와 문구는 호출자가 넘기는 명시적인 경계입니다. 실제 기능에서는
프로젝트 서비스와 다국어 사전에 연결해야 합니다. 예제의 필드, 타입, 페이지네이션
방식, 간단한 레이아웃은 제품 요구사항이나 승인된 디자인을 의미하지 않습니다.
Next.js·React·TanStack Query·RHF/Zod 버전과 UI primitive API, alias, 정책 모듈은
대상 프로젝트에서 확인합니다. 한국어 locale과 경로를 포함한 예시 값은 기본 정책이
아니며 실제 스택·라우팅·API·인증·디자인 계약에 맞춰 적용합니다.
예제를 위해 가짜 API나 컴포넌트 갤러리를 기본 앱에 남기지 않습니다.

## 다른 Skill과의 관계

- `react-ui-ux`: 관련 작업에서 참고하는 접근성, 안정적인 비동기 UI, 데이터와 변경 요청의 안전성.
- `frontend-patterns`: 요청된 기능에 위 원칙을 적용하는 조건부 구현 예제.
- 선택적인 성능 가이드: 위 계약과 기존 아키텍처를 보존하는 범위의 성능 개선.

특정 marketplace Skill 설치나 companion 문서의 일괄 로딩은 필수 조건이 아닙니다.

상위 지시를 준수하며 명시적인 사용자 요청과 대상 저장소 지침, API·인증·인가·
다국어·디자인 규칙을 Skill 예제보다 먼저 따릅니다. 특정 우선순위 파일이나
클라이언트의 자동 규칙 탐색을 전제로 하지 않습니다.

## 프로젝트별 조정과 업데이트

이 Skill은 개인이 작성하고 dotfiles에서 유지하는 가이드입니다. 대상 프로젝트의
요구사항과 기존 패턴에 맞게 적용하며, 별도의 템플릿 정책이나 필수 sibling 문서,
lockfile, 중앙 배포 체계를 전제로 하지 않습니다.

공통 기법이 발전하면 변경 근거와 검증 결과를 검토한 뒤 필요한 프로젝트에 명시적으로
반영합니다. 예제를 복사했다고 미래 변경이 자동 배포되지는 않습니다. 품질 확인은
현재 작업에서 허용한 범위와 프로젝트의 기존 도구를 따릅니다.
